# Social Brief

The Social Brief is the Social Media Operations Layer's daily output, generated by
`social_brief.py`. It mirrors the Morning Brief's pattern (Memory Layer + Communication
Layer): read real data, classify it, cross-reference memory, and print one actionable
summary.

**Generate it:**
```bash
cd AI_SYSTEMS_INVENTORY/agency-os
python3 social_brief.py --source sample          # sample data (always works)
python3 social_brief.py --source omnisocials     # real data via OmniSocials API
python3 social_brief.py --source omnisocials --no-save
```

## Required Sections

Every Social Brief contains exactly these sections, in this order:

1. **Scheduled Content** - upcoming posts/stories/reels that are queued to publish,
   with client, platform(s), type, and scheduled time.
2. **Published Content** - posts published since the last brief, with per-post
   impressions/engagements/likes/comments/shares (from `analytics:post` /
   `posts:list --status published`).
3. **Engagement Metrics** - aggregate totals across the published content above
   (impressions, engagements, likes, comments, shares). For weekly/monthly rollups,
   `analytics:overview --period 7d|30d` is used instead.
4. **Top Performing Posts** - the top 2 published posts by engagement count, called
   out for repurposing.
5. **Posts Requiring Action** - anything that needs a human: `failed` posts (API
   error), `scheduled` posts whose `scheduled_at` has already passed without
   publishing ("missed schedule"), and `draft` posts awaiting client approval.
6. **Recommended Next Actions** - one line per item in "Posts Requiring Action" plus
   a repurposing suggestion for each "Top Performing Post". If nothing needs
   attention, prints "Nothing urgent - continue with the planned content calendar."

## Memory

After each non-`--no-save` run, `social_brief.py` appends a KPI snapshot to
`memory/social_memory.json` (`brief_history`): `generated_at`, counts of
published/scheduled/overdue/failed/draft posts, `total_impressions`,
`total_engagements`, and `top_post_id`. This is the data source for month-over-month
KPI tracking in `SOCIAL_MEDIA_OS.md`.

## Real Data (`--source omnisocials`)

`social_brief.py --source omnisocials` shells out to
`omnisocials-agent-skills/scripts/omnisocials.js posts:list --json` and
`accounts:list --json`, which require `OMNISOCIALS_API_KEY` to be set (see
`OMNISOCIALS_IMPLEMENTATION_STATUS.md` for current connectivity status). The
classify/aggregate/rank/report logic does not change between sample and real data -
only the input source does.
